# V2 安全模型

## 权限边界

社会身份 != 销售授权 != 钱包所有权 != 支付授权。独立 economy policy 默认关闭；
V1 auto_with_rules 不授予商品上架权。Agent 可在明确提案授权后生成草稿；
发布/改价/库存调整/下架由主人在可信 UI 确认具体版本，服务端及 SQL 双重校验。
未来付款必须再确认订单金额、币种、收款方、网络、期限和摘要；不可沿用商品审批。

## 威胁与措施

| 威胁 | 控制与验收 |
| --- | --- |
| IDOR/伪造主人 | 认证层覆盖身份头；SQL 验证 Agent 当前主体与用户 membership；双用户测试 |
| 草稿泄露 | RLS 默认拒绝，公开接口限定 state+visibility+列；直接 REST 越权测试 |
| 旧审批/所有权转移 | 版本锁、主体快照、转移撤销；旧主人/新主人均不得复用旧审批 |
| 并发改价/超卖 | SQL 事务条件更新、固定锁顺序；订单按版本预留库存 |
| 重放请求 | 主体/Agent/操作/幂等键绑定内容，冲突返回 409；签名协议沿用 V1 |
| 提示注入 | 文本只展示，不能调用支付/钱包/文件工具；输入字段白名单与敏感扫描 |
| 私人文件售卖 | 初期不接上传/文件抓取；后续独立资源授权与私有桶交付 |
| 伪造支付/重复回调 | 原始 body 验签、provider object 核验、唯一 inbox、原子账本 |
| SSRF/恶意图片 | 初期 images 为空；后续受控存储对象，禁止任意 URL 抓取 |
| XSS/隐私 | React 文本渲染；地址/支付信息不进入公开商品、日志或模型 |

RLS 不替代服务端 service_role 校验。所有 SECURITY DEFINER 函数固定 search_path，
撤销 public/anon/authenticated execute，仅向 service_role 授权。
发布敏感扫描不能证明不存在隐私或非法商品；主人确认和平台审核仍有必要。
审计记录动作、版本、actor、对象，不记录 API key 或钱包私钥。
未来资金表不可客户端删除，付款不写控制台日志；网络请求超时进入待核验状态。

未完成风险：卖家身份核验、禁售品审核、文件安全扫描、MFA/付款 step-up、
税务/争议流程、对账与备份恢复演练、独立安全评审，均须真实资金上线前完成。
