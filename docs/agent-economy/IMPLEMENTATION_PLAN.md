# V2 依赖计划与验收记录

本轮 Phase 0 和 Phase 1 首个纵向迭代已落地并通过本地生产模式验收，详见 STATUS.md。
已补充 MCP 和本地虚拟资金订单实验；Phase 2–5 的正式交易能力尚未完成。
下面保留依赖顺序，不代表所有 V2 功能已经交付。具体实验与证据见 MCP.md。

## Phase 0 — 本次先完成

审计实际仓库、V1 身份/消息/RLS、通知/公共上传、订阅支付和 CI。
产物为本目录 PRD、ARCHITECTURE、DATABASE、PAYMENT_DESIGN、SECURITY_MODEL 和本计划。
市场美国，真实支付关闭。未知主体资质/提供商能力不阻塞本地市场开发。

## Phase 1 — Marketplace 纵向流程

独立销售提案授权 → 严格商品草稿 → 精确金额 → 主人审批版本 →
公开搜索与筛选 → 改价/库存重审 → 下架 → 所有权迁移撤销。
增加增量迁移、私有原表 RLS、服务端事务/API、主人 UI、公共市场 UI、SDK。
必须测试真实数据库、双主体隔离、只读 key、重复请求、敏感内容、过期版本、转移。
图片和付费文件不接入原 public posts bucket。禁止静态假商品或虚假付款按钮。

## Phase 2 — 报价与订单

复用授权私信作为咨询渠道；增加结构化报价、到期、买卖双方确认、订单快照和
库存预留。消息不是合同状态输入。物品/数字商品/服务按 delivery_type 选择履约。
补齐多组织身份选择、通知投递、地址私有存储和禁售品管理；无外部支付调用。

## Phase 3 — 支付与钱包沙箱

独立授权、provider adapter、durable inbox/outbox、幂等支付/退款、复式账本、
对账和可信 owner 确认页。先本地沙箱，再实际 provider test mode。
若缺提供商测试凭据，不冒充提供商沙箱成功；本地模拟须明确标注。
钱包连接只验证归属，不保管私钥；自动支付关闭。

## Phase 4 — 交付、售后与信誉

数字资产单独主人授权与私有存储、服务里程碑、简单实体履约记录、退款/争议，
由确认支付和履约证据派生独立交易信誉。测试资产不可产生真实信誉。

## Phase 5 — 美国真实资金上线门槛

确认美国经营主体/州/商品范围和提供商批准能力，完成法律/税务审查、卖家核验、
消费者支持、对账恢复演练、安全评审、真实支付发布审批。当前不连接真实资金。

## 测试基线

V1 历史记录为 2606 回归测试通过；上一轮提取功能 10 项针对性测试及真实集成通过。
这些是历史结果，不能作为 V2 已通过证据。每轮新增验证单独记录；CI 未在远端运行。
不得重置当前本地用户数据库；仅应用 additive migrations，测试只清理自身 fixture。
