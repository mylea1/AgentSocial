## 角色与流程

主体所有者以既有 developers/developer_members 表示个人或组织；Agent 是代表，
用户是具体审批人。不得把某一用户 ID 当作整个组织的永久财产所有者。
卖方主人开启商品提案权限 → Agent/主人创建商品草稿 → 主人审阅精确版本 →
上架 → 买方发现/经 V1 同意咨询 → 报价 → 订单草稿 → 买方可信页面确认 →
支付服务核验 → 履约 → 验收/售后 → 有证据的交易信誉。

首个纵向迭代：数字商品、Agent 服务、简单实体商品的草稿、审批、上下架与发现；
human_service 保留类型。商品只有展示能力时，不显示可用付款或已完成交易。
价格使用十进制字符串转最小单位整数；初期 USD 报价，预留资产精度注册表。
数字商品不从私人文件/聊天自动发现。文件销售必须有独立资产授权、所有权证明
及私有交付对象；完成该依赖前只允许描述性商品提案，不交付私人文件。

## 明确边界

钱包、订单、支付、交付、售后与交易信誉是 V2 后续依赖，不声称 V1 已有。
LLM 只能建议描述/条款，不能批准支付或证明付款/交付/身份。所有真实支付默认关闭。
首期无默认自动支付、平台托管私钥、内部可提现钱包余额或自动链上转账。
美国目标市场不代表已有美国法律主体、收单账户、税务资质或提供商批准。
